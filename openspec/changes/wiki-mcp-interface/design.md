# Design: Read-Only MCP Interface Over the Published Wiki

## Technical Approach

Promote the validated `spike/mcp/` logic into two tested units joined by one versioned file
contract: a zero-dependency **index generator** in the root package (runs post-`astro build`) and an
**MCP server** in an `mcp-server/` npm workspace. The generator writes `dist/mcp/docs-index.json`;
the server loads it at start, validates it, and refuses to run on an unrecognised shape. The spike's
extraction, BM25-lite scoring, snippet windowing and origin middleware are promoted essentially
unchanged — they are measured-correct (190 sections byte-identical to the deployed site; 5/6 queries
correct at rank 1) — and gain module boundaries, hard-fail guards and tests.

## Architecture Decisions

### Decision: `mcp-server/` is an npm workspace, not a standalone package or root-level code

| Option | Trade-off |
|---|---|
| Standalone package + own lockfile | Clean boundary, but the VPS builds the site anyway (it needs `astro build` for the index), so the second install saves nothing there; and the AC8 client test would need a duplicate `@modelcontextprotocol/sdk` pin that can silently drift from the server's |
| Everything in root `package.json` | One install, but the static site's dependency graph absorbs `express`/SDK/`zod`, and the server loses a `version` field of its own — which the deployment spec requires as the process release identifier |
| **npm workspace (chosen)** | One root `npm ci` hoists the SDK so server and AC8 client test share one pinned version; `mcp-server/package.json` still declares the runtime deps and owns the release identifier; `npm ci --workspace mcp-server --omit=dev` stays available if index delivery ever stops requiring a site build |

**Rationale**: the deciding constraint is that the AC8 client-consumption test must exercise the same
SDK version the server runs. Hoisting gives that for free. Cost paid: Netlify installs three runtime
packages it never executes (install seconds only — nothing enters `dist/`). If npm ever nests rather
than hoists the SDK, add the identical pin to root `devDependencies`.

### Decision: index contract is versioned, build-only, never committed

```jsonc
{
  "schemaVersion": 1,                 // integer; server refuses any other value
  "generatedAt": "2026-09-01T00:00:00.000Z",  // ISO 8601 UTC
  "commit": "c48e766",                // short SHA, or "unknown" outside a checkout
  "sectionCount": 190,                // integer, === sections.length
  "base": "https://docs-gentle-ai.netlify.app",
  "locales": ["en", "es"],
  "sections": [
    { "id": "engram", "locale": "en", "level": 2, "title": "…", "url": "…", "text": "…" }
  ]
}
```

**Build identity** = `{ schemaVersion, generatedAt, commit, sectionCount }`. Returned verbatim on
`/health` and as the `index` field of every tool response.

**Location**: `dist/mcp/docs-index.json` — inside already-gitignored `dist/`, so it is build-only by
construction. Committing a 190-section generated file would create a merge conflict on every docs
edit and instantly become the second source of truth AC6 exists to eliminate. Free side effect:
Netlify publishes it at `/mcp/docs-index.json`, useful for diffing without depending on it.

**Unrecognised shape**: the server validates before `listen()` — `schemaVersion` mismatch, missing
top-level field, empty `sections`, or any section missing `id`/`locale`/`title`/`url`/`text` →
descriptive `stderr` message and `process.exit(1)`. **Fail closed.** A down MCP process is correct
here because the static site is unaffected by design (deployment spec); a process serving a
half-understood index is not.

### Decision: keep regex extraction; do not adopt an HTML parser

**Rejected**: `cheerio`/`linkedom`/`node-html-parser`. The markup is generated by two `.astro`
components *in this repository* — it is not third-party or user-authored, so the unpredictability a
parser guards against does not exist. A parser would also add a runtime dependency to the **site
build path** (root package, every Netlify build), which is the one graph worth keeping at four
devDependencies. The spike's regex is measured correct against the real output.

Regex's actual risk is *silent mis-extraction*, not missing structure, and a parser does not fix
that either. It is bounded instead by explicit guards, matching the throw-on-mismatch convention of
`scripts/generate-banner.mjs`: throw on missing canonical link, missing `<main>`, zero headings,
**any section with empty `text`**, and `sectionCount < MIN_SECTIONS`. Extraction lives behind one
pure function in `scripts/lib/extract.mjs`, so a later parser swap is contained and already covered
by units.

### Decision: Playwright's `testDir` does not move — Vitest is scoped around it

`playwright.config.ts` **already has** `testDir: './tests'`; the proposal's "Playwright gets an
explicit `testDir`" describes an existing fact, not a change. Moving it to `e2e/` (the research
suggestion) would force relocating `tests/docs.spec.ts-snapshots/` because
`snapshotPathTemplate` is keyed on `{testDir}`, risking 4 committed baselines and 14 passing tests
for zero functional gain. **Rejected.**

Instead, two orthogonal axes — either alone would suffice, both together mean one mistake cannot
cause a collision:

| Runner | Directory | Suffix |
|---|---|---|
| Playwright | `tests/` only | `*.spec.ts` |
| Vitest | never `tests/` | `*.test.mjs` |

```js
// vitest.config.mjs  (.mjs matches astro.config.mjs and scripts/*.mjs; keeps it out of `astro check`)
import { defineConfig, configDefaults } from 'vitest/config';
export default defineConfig({
  test: {
    environment: 'node',
    include: ['scripts/**/*.test.mjs', 'mcp-server/**/*.test.mjs'],
    exclude: [...configDefaults.exclude, 'tests/**', 'dist/**'],
  },
});
```

No `getViteConfig()`: the suites import plain `.mjs` modules with no Astro alias, `.astro` import or
`astro:` virtual module. Prototype-first per research — add it only if resolution actually breaks.

`playwright.config.ts` gains per-project `testMatch` so the new wire tests never run under the two
browser projects, plus a second `webServer` entry:

```ts
projects: [
  { name: 'chromium-desktop', testMatch: 'docs.spec.ts', /* unchanged */ },
  { name: 'chromium-narrow',  testMatch: 'docs.spec.ts', /* unchanged */ },
  { name: 'mcp-http', testMatch: 'mcp-*.spec.ts', use: { baseURL: 'http://127.0.0.1:3111' } },
]
```

The MCP `webServer` runs against a **committed fixture index**
(`mcp-server/test/fixtures/docs-index.json`), not `dist/`. This removes a start-order race with the
site build, and makes AC8's "exact returned content for a known section" a stable assertion instead
of one coupled to live docs text.

### Decision: schema validation is the primary error path for unsupported locale

`locale` stays `z.enum(['en','es'])` so the advertised schema documents the domain; the SDK rejects
`fr` with a validation error naming the received value — explicitly an error, never an empty
success, satisfying the spec. Handlers keep a defensive locale branch for the wire-level tests that
post raw JSON-RPC.

## Data Flow

```
  git checkout (one commit)
        │
        ▼
  npm run build ── astro build ──► dist/index.html, dist/es/index.html
        │                                    │
        │                                    ▼
        └──► node scripts/build-mcp-index.mjs
                      │  extract.mjs: <main> → h2/h3[id] → sections
                      │  guards: canonical? main? headings? empty text? MIN_SECTIONS?
                      │  EN/ES id parity ──► mismatch ⇒ exit 1, NO file written
                      ▼
             dist/mcp/docs-index.json   {schemaVersion, generatedAt, commit, sectionCount, …}
                      │
        ┌─────────────┴──────────────┐
        ▼                            ▼
  Netlify publishes           systemctl restart gentle-ai-docs-mcp
  static site + index                │
                              index-store.mjs: validate ⇒ exit 1 on unknown shape
                                     │
                              express :3111 ── host+origin middleware ── POST /mcp
                                     │        (fresh McpServer + transport per request)
                                     ▼
                              search.mjs / tools.mjs ──► result + build identity
                                     │
                              nginx (TLS, limit_req) ──► agent client
```

## Deployment Topology

```
/srv/gentle-ai-docs   (git checkout, deploy user)
deploy.sh — ONE step, the AC6 staleness mitigation made real:
  git fetch --prune && git checkout <ref> && npm ci \
    && npm run build            # regenerates dist/ AND dist/mcp/docs-index.json
    && sudo systemctl restart gentle-ai-docs-mcp
```

`gentle-ai-docs-mcp.service`: `WorkingDirectory=/srv/gentle-ai-docs`,
`ExecStart=/usr/bin/node mcp-server/src/server.mjs`,
`EnvironmentFile=/etc/gentle-ai-docs-mcp.env` (`PORT=3111`, `ALLOWED_HOSTS`, `ALLOWED_ORIGINS`,
`DOCS_INDEX_PATH`), `Restart=on-failure`, `RestartSec=5`, `NoNewPrivileges=yes`,
`ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `MemoryMax=512M`.

nginx: `limit_req_zone $binary_remote_addr zone=mcp:10m rate=30r/m;` and
`location /mcp { limit_req zone=mcp burst=10 nodelay; client_max_body_size 1m;
proxy_pass http://127.0.0.1:3111; proxy_read_timeout 30s; proxy_buffering on; }` — buffering is safe
precisely because the stateless design has no SSE stream. `/health` proxied on an internal path.

**Rejected**: server fetches the index over HTTPS from the published site at start. It would remove
the build toolchain from the VPS, but adds a boot-time network dependency, a 404/partial-read
failure mode, and lets the process serve an index built from a different commit than its own code —
breaking the guarantee the `schemaVersion` contract is there to give.

## Interfaces / Contracts

Every tool response carries `{ …payload, index: <build identity> }`. Errors are
`{ isError: true, content: [{ type: 'text', text: '<reason naming the offending value>' }] }`.

| Tool | Input | Success | Error |
|---|---|---|---|
| `search_docs` | `query: string`, `locale?: 'en'\|'es'`, `limit?: 1..20` (default 5) | `{query, locale, count, results[{id,title,locale,url,snippet≤400}]}` | empty/whitespace `query`; unsupported `locale`. Zero matches for a valid query is **success** with `count: 0` |
| `list_sections` | `locale?: 'en'\|'es'` | `{count, sections[{id,title,level,locale}]}` — no body text | unsupported `locale` |
| `get_section` | `id: string`, `locale: 'en'\|'es'` (**required**) | `{id,locale,title,level,url,text}` — untruncated | unknown `id` for that `locale`; unsupported `locale` |

## Testing Strategy

| Layer | What | How |
|---|---|---|
| Unit (Vitest) | Extraction guards, `<pre>` line breaks, link href retention, parity failure, index-store validation, BM25-lite ranking, stopwords, snippet bound | `*.test.mjs` over HTML and JSON fixtures |
| Integration (Playwright `request`) | `POST /mcp` JSON-RPC, 405 on GET/DELETE, missing `Origin` accepted, `Origin: null` and untrusted rejected, host allow-list, `/health` identity, all typed error paths | `tests/mcp-http.spec.ts`, `mcp-http` project, fixture-backed server |
| E2E (Playwright + SDK) | AC8: `initialize`, `tools/list`, `tools/call`; negotiated protocol version, advertised schemas, exact fixture content | `tests/mcp-client.spec.ts` |
| Regression | The 14 existing browser tests | Unchanged, unmoved snapshots |

## Threat Matrix

The reference matrix targets git/PR/shell automation; this change has none of it.

| Boundary | Applicability |
|---|---|
| Documentation-like paths | N/A — nothing is classified or executed by path; the generator only reads two fixed `dist/` HTML files |
| Git repository selection | N/A — no `git -C` or repo selection in product code; `commit` comes from `$COMMIT_REF`/`git rev-parse` in the build, defaulting to `"unknown"` |
| Commit state | N/A — no VCS writes |
| Push state | N/A — no push automation |
| PR commands | N/A — no PR automation |

Project-specific boundary (the real adversarial surface), all carried into `tasks.md` as RED tests:

| Case | Safe behaviour | Failure behaviour |
|---|---|---|
| `Origin` absent | Proceed | — |
| `Origin: null` / untrusted host | — | `403 forbidden origin` |
| `Host` outside allow-list | — | Rejected before MCP processing |
| `GET`/`DELETE /mcp` | — | `405`, client completes over POST alone |
| Body > 1 MiB | — | Rejected by `express.json({limit:'1mb'})` and nginx |
| `get_section` `id` with `../`, `%00`, 10 KiB | — | Typed unknown-id error; `id` is a map key, never a filesystem path |
| Index unknown `schemaVersion` | — | Exit 1 before `listen()` |

Per-slice revert as in the proposal. No data migration. `spike/mcp/` is removed only after slice 3.

must be extracted.**

**Slice 2 does not hold at 350–400** — the honest estimate is ~750 (six modules, two unit suites, a
fixture index, a wire suite and a Playwright config change). **Seam: the transport boundary.** 2a is
pure functions with zero `express`/SDK imports and is fully unit-testable; 2b adds HTTP, tool
registration and the wire suite on top. Slice 1 was estimated at 250–350 and lands ~470 with the
Vitest wiring TDD requires up front, so it splits at the module/CLI seam.

**Slice 6 is extracted deliberately**: 329 deletions of superseded throwaway code carry near-zero
review cognition but would consume most of slice 3's budget. Standalone, or `size:exception`.
